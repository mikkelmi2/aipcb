# M15 — going public: delivery report

One milestone with a hard ordering, because one of its steps is the only
irreversible one in the project so far. The hygiene sweep ran first, found what it
was looking for in a place nobody had thought to look, and then found something
much more important: **the premise of the milestone was wrong.** The repository was
already public, and had been for two days.

Everything below was measured on 2026-08-23 on the development machine (16 cores,
30 GB RAM, Linux 7.0.0-29-generic), against gitleaks 8.28.0, KiCad 9.0.8, and
images pulled that day. Where a number is a projection rather than a measurement it
says so in the same sentence.

## 1. M15a — the hygiene sweep

### 1.1 What was scanned, and how

Not HEAD. The whole object database.

**gitleaks 8.28.0**, `git --log-opts="--all"`: **59 commits, ~3.97 MB, 0 leaks.**
Run again after the history rewrite, and again on a fresh clone: 0 both times.

**A manual pass over every blob that has ever existed.** `git cat-file
--batch-all-objects` yields 563 blobs; each was decompressed and searched for
`/home/<user>`, `/Users/<user>`, `C:\Users`, the author's username, RFC-822
addresses, RFC-1918 addresses, `.local`, `ssh-rsa` and PEM private-key headers.

**Four hits, all four false positives**, which is worth writing down because a
sweep that reports zero is a sweep you should not trust:

| Hit | Why it matched | Verdict |
|---|---|---|
| `−10.2` × 3, in `docs/reports/m13.md` | a dB figure matched the `10.x.` private-range pattern | not an address |
| `/sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service/` | a cgroup path matched the email pattern | UID 1000 is the default first user on any Linux box; it identifies nobody |

**The two committed PDFs** — M14's rendered schematics, and the largest binaries in
the repository — were checked for embedded provenance. `/Author ()` is empty,
`/Producer (KiCad PDF)`, `/Creator (Eeschema-PDF)`, no filesystem paths. Clean.

### 1.2 What the sweep actually found

Nothing in any *file*. Both findings were in **commit metadata**, which no
`.gitignore` reaches and no content scan sees:

1. **The author's personal email on all 59 commits**, as both author and committer.
2. **`Claude-Session: https://claude.ai/code/session_…` trailers on all 59
   commits**, three distinct session identifiers.

Neither is a secret. Both are permanent once public. Presented rather than decided,
per the guardrail; the decisions taken were **rewrite the address to the GitHub
noreply form** and **strip the session trailers**, keeping `Co-Authored-By`, which
honestly credits the AI authorship the README now advertises.

### 1.3 And then the premise collapsed

While checking name availability, the GitHub API answered a question nobody had
asked:

```
GET https://api.github.com/repos/mikkelmi2/aipcb   (unauthenticated)
  private     False
  visibility  public
  created_at  2026-08-21T07:48:34Z
  forks 0 · stars 0 · watchers 0
```

The repository was **created public**, two days before this milestone began. M15e —
"make the repository public" — described something that had already happened, and
M15a's gate had been guarding a door that was standing open.

This was verified rather than inferred, and the exposure demonstrated directly:

```
GET /repos/mikkelmi2/aipcb/commits/3bb475e…   → 200
author email on GitHub: <the personal address>
```

That is the **pre-rewrite** commit, still resolvable by SHA. `3bb475e` is
deliberately *not* remapped to its post-rewrite hash by §8's citation sweep — it is
evidence about an object that existed under that name on GitHub, and rewriting it
would make the sentence false. It is the one hash in this repository's
documentation that is meant not to resolve locally.

**What this changes, honestly.** On a never-public repository, a history rewrite is
an erasure. On an already-public one it is **remediation, not erasure**: a
force-push makes every future clone clean and the branch history clean, but the
orphaned objects stay reachable by SHA on GitHub until it garbage-collects them,
which for a public repository can require asking GitHub Support.

**What could not be established.** Whether the address reached third-party archives
that record public push events. The repository's 22 available public events were
checked and **none of their payloads carry a commit list**, so no exposure was found
by that route — but the absence of a commit list in today's API window is not proof
about what was captured two days ago, and this report will not pretend otherwise.

**Mitigating facts, measured:** 0 forks, 0 stars, 0 watchers, no description, no
licence, never announced. There is no evidence anyone has looked at it.

The decisions taken on this were **force-push only** — accepting that old SHAs stay
resolvable until GitHub collects them — and **make the repository private for the
remainder of the milestone**, finishing M15 as it was written and flipping back at
the end.

### 1.4 The rewrite, and the thing that nearly got missed

`git filter-branch` over `--all`, rewriting both author and committer address and
dropping `Claude-Session:` lines from every message.

**The rewrite is proved not to have touched content.** Every commit's tree hash was
recorded before and after: **all 59 identical, byte for byte.** Only metadata moved.

Then the part worth reading. After deleting `refs/original/`, expiring every reflog
and running `git gc --prune=now`, the old address was *still present*:

```
$ git log --all --format='%ae %ce %B' | grep -c '<the old local-part>'
10
$ git for-each-ref
  <only refs/heads/master and refs/remotes/origin/master, both rewritten>
```

Ten commits, reachable, belonging to no ref. `git rev-list --all --not --branches
--remotes` named them: the first ten commits of the original history, held alive by
**a linked worktree in a dead session's scratchpad** —
`.git/worktrees/m7base`, a detached checkout at commit 10 made for an M7 comparison
in a session that ended weeks ago. `filter-branch --all` does not rewrite worktree
HEADs, and `gc` will not prune what a worktree HEAD roots.

`git worktree prune` would not remove it, because the directory still existed. It
was checked for uncommitted work (there was none — a pristine checkout), removed,
and the repository collected again.

The lesson generalises past this repository: **`for-each-ref` showing a clean set of
refs is not proof that a history rewrite is complete.** The check that catches it is
`git rev-list --all --not --branches --remotes`, and it should be part of any
rewrite procedure.

### 1.4a And then the rewrite undid itself

Worth recording because it took ninety seconds to happen and would have shipped.

The M15 commit was made with `git commit -s`, and came out authored by
**the old personal address** — the one the entire rewrite existed to remove.
`git config --show-origin user.email` explained it: `file:.git/config`. The
repository had a *local* identity override, and rewriting history does not touch
configuration. The next commit after any such rewrite reintroduces the address,
and `-s` helpfully stamps it into a `Signed-off-by` line as well.

Fixed by setting the repository-local `user.email` to the noreply form and
amending the commit — author, committer and sign-off. Then re-verified: one
identity across all 60 commits, 0 occurrences of the old address, gitleaks clean.

The general lesson pairs with the one above: **a history rewrite is not finished
when the history is clean.** It is finished when the thing that writes the next
commit has been changed too.

### 1.6 Repository cleanliness

**210 files tracked; 210 files ever added; zero deletions in the entire history.**
Nothing junk was ever committed and then removed — there was nothing to find. No
`out/`, no caches, no virtualenv, no local editor or agent configuration.

The largest objects are the two M14 schematic PDFs (162 945 and 83 371 bytes) and
the golden KiCad files. Both PDFs belong: they are the M14 report's evidence.

`.gitignore` was rewritten and three gaps closed, each verified with
`git check-ignore` rather than assumed:

* `.claude/` was ignored only via `.git/info/exclude`, which is local and
  uncommitted — every contributor would have had to rediscover it.
* An example's build output (`examples/*/*.kicad_pcb`, `.kicad_sch`, `.kicad_pro`,
  the lib-tables) was untracked but unignored, so `git status` was noisy after any
  build. The patterns are **scoped to `examples/`** on purpose: the golden copies
  under `tests/golden/` are tracked and are what byte-stability is measured
  against. Verified: `git ls-files | git check-ignore --stdin --no-index` returns
  **0 files** — nothing already tracked became ignored.
* A first draft of the file used trailing comments (`out/    # …`). git does not
  support them; the pattern would have been the whole line including the comment.
  Caught by testing the file rather than reading it:

  ```
  with trailing comment, is out/x ignored?  NO
  ```

### 1.7 Third-party content audit

**No vendored code.** In particular `src/aipcb/kicad/sexpr.py` is original work
written *instead of* `kiutils`, not derived from it — ADR 0001 records the
evaluation. `kiutils` (GPL-3.0) is present in the development virtualenv as a
leftover of that evaluation and is **imported nowhere**: `grep` over `src/`,
`tests/` and `examples/` for `import kiutils` returns nothing, and it is not a
declared dependency.

**KiCad library data is embedded, and the licence permits it.** KiCad inlines
referenced symbol definitions into every `.kicad_sch` it writes, so the designs
under `tests/golden/` contain library data. The licence was fetched and read rather
than recalled: the KiCad libraries are CC-BY-SA 4.0 **with an exception** waiving
article 3 for "these designs and any generated files which use data provided as
part of the Licensed Material". Generated design files are exactly that. The
exception is withdrawn only for redistributing the libraries *as a collection*, and
the repository contains **no `.kicad_sym`, no `.kicad_mod`, no `.pretty` directory
and no library table** — checked, not assumed. Attribution is offered in `NOTICE`
as courtesy rather than obligation.

**External tools are invoked, never embedded.** Every one runs as a separate
process; nothing links or imports. Licences verified from each project's own
repository rather than from memory:

| Tool | Licence | How it is used |
|---|---|---|
| KiCad 9.x | GPL-3.0-or-later | `kicad-cli` subprocess; `pcbnew` in a helper process that imports nothing from aipcb (ADR 0009) |
| Freerouting 2.x | GPL-3.0 | run by the user; aipcb writes DSN and reads SES |
| openEMS | GPL-3.0 | inside a container image |
| gerber2ems | Apache-2.0 | inside the same image, built by the user from Antmicro's Dockerfile, not distributed here |

**No datasheet text is reproduced.** One datasheet URL is linked. The SATA skew
discussion in `examples/pcie-sata/design.yaml` cites table numbers and paraphrases;
connector pinouts are factual contact assignments.

**Verdict: M15a passed**, with the two metadata findings resolved by decision and
the already-public status recorded as an accepted, partly-irreversible exposure.

## 2. M15b — the licence package

| Artefact | What it is |
|---|---|
| `LICENSE` | Apache-2.0, 202 lines, fetched from apache.org |
| `NOTICE` | 91 lines; the five sections of §1.7 written down where a lawyer would look |
| SPDX headers | **123 Python files**, applied by `tools/add_spdx.py` |
| `pyproject.toml` | `license = { text = "MIT" }` → `license = "Apache-2.0"` with `license-files` |

The MIT line is worth flagging: the project's own packaging metadata claimed a
different licence from the one the milestone specifies, and would have shipped that
claim to PyPI.

`tools/add_spdx.py` has a `--check` mode that CI runs, so the next file added
cannot quietly lack a header. Headers go **above** the module docstring — a comment
is not a statement, so `__doc__` is unaffected.

`tools/check_licenses.py` walks the closure of the *runtime* dependencies only —
dev tools are not redistributed, so their licences do not propagate. Measured:
**16 distributions, every one permissive.**

```
  ok    numpy              BSD-3-Clause AND 0BSD AND MIT AND Zlib AND CC0-1.0
  ok    pydantic           MIT
  ok    shapely            BSD 3-Clause
  ok    typing-extensions  PSF-2.0
  …
16 distributions in the runtime closure of 4 declared roots
all permissive (BSD/MIT-family or equivalent)
```

It failed on its first run — `shapely` declares `BSD 3-Clause` with a space and the
allowlist only had the hyphenated SPDX form. That is the check working: it refuses
a licence it does not recognise instead of pattern-matching optimistically.

**DCO.** `tools/check_dco.py` verifies that every commit in a pull request carries a
`Signed-off-by` matching *its own author* — a sign-off copied from elsewhere
certifies nothing. Merge commits are exempt. It is standard library rather than a
marketplace action, so no unreviewed third-party code runs in CI on every
contributor's pull request. Verified in both directions on a throwaway repository:
a signed commit passes, an unsigned one fails and names itself. It applies to pull
requests, so the unsigned existing history is not retroactively broken.

### 3.3 The simulation plot, and the plot that was wrong

The first version read the Touchstone files directly, did its own mixed-mode
conversion, and drew **insertion loss above 0 dB** across the whole simulated span —
more energy leaving the pair than entered it.

The project already knows about that failure mode. `aipcb.si.results` carries a
calibrated threshold for it, and on this very board it reports:

```
si-not-physical | PCIE_TXN+PCIE_TXP: |Sdd21| reaches 1.22, which is more energy
                  than went in; the extraction is not physical and the numbers
                  below are not usable
```

So the README script was busy drawing conclusions the program it advertises
explicitly refuses to draw. It now reads each pair's `result.json` — the same
metrics the tool turns into findings — and plots two things against their
thresholds: differential impedance as a deviation from each pair's declared target,
and worst return loss in band. The pair with the unusable extraction is drawn
hollow and labelled rather than silently included.

What the finished plot says is not flattering, which is the point: **six of the
eleven pairs land more than 10% from their declared impedance**, REFCLK worst at
−41.7%.

**The data is current, and that was verified rather than assumed.** A full
eleven-pair solve costs **15 387 s — 4 h 16 m**, so re-running it for a README image
was not on. A previous session's complete run was found, and `aipcb simulate
--dry-run` was used to compare its per-pair geometry digests against today's board:
**10 of 11 matched exactly**; `PCIE_TX` had changed. Seeding the cache with the ten
and re-simulating the one cost **242 s** and made all eleven current.

### 3.4 The quickstart, tested in a clean environment

Run in a bare `python:3.12-slim` container with no KiCad and no cached wheels for
the project:

```
### install (venv + pip install -e .) : 7 s
--- aipcb validate examples/usb-port/design.yaml
    OK   info[kicad-libraries-missing]: KiCad's symbol and footprint libraries
         were not found, so symbol and footprint bindings were not verified
--- aipcb summary  OK        --- aipcb schema  OK        --- aipcb version  OK
--- aipcb build examples/usb-port/design.yaml
    EXIT 1   with a traceback
    SymbolNotFound: symbol library 'Connector' not found (searched: no directories)
```

Two things fell out of that, and neither would have been found by reading:

One more correction, and the fault for this one lies with M15 rather than with
what it inherited. The worked diagnostic in the *new* README was **written from
memory rather than captured**, and named the wrong net entirely. The pre-M15 text
had been accurate — its only error was a line number that the source had since
moved past, 47 where the tool now says 53. Both are fixed by running the command
and pasting what came out, which also revealed that this design emits **two**
errors and not one:

```
examples/usb-port/design.yaml:53:3: error[asymmetric-diff-pair]: net 'USB_DP'
names 'USB_DM' as its differential partner, but 'USB_DM' names USB_DPP
examples/usb-port/design.yaml:53:3: error[unknown-diff-pair]: net 'USB_DM' names
'USB_DPP' as its differential partner, but there is no such net
```

A README that quotes its own program should quote it verbatim, and the only way to
be sure is to run it.

**The README was wrong about KiCad.** Both the old README and the first draft of the
new one said KiCad was needed "for the check and export commands; everything else
runs without it". `aipcb build` needs KiCad's symbol and footprint libraries to
compile anything. Fixed: the README now says KiCad is the backend and names the four
commands that genuinely run without it.

**`aipcb build` violates the project's own honest-stop rule.** `validate` handles
the missing-libraries case properly, with an `info[kicad-libraries-missing]`
diagnostic. `build` raises `SymbolNotFound` and prints a traceback. Filed rather
than patched, per the milestone's scope: it is an error-path change that needs its
own test, and it is the first thing a visitor without KiCad will hit.

## 4. M15d — CI, and the KiCad dependency

The full reasoning and every measurement is [ADR 0013](../decisions/0013-ci.md).
The short version, and the finding that changed the design.

### 4.1 What the runner can do

`docker.io/kicad/kicad:9.0.8` exists, is **1.7 GB**, and pulled cold in **44.7 s**.
Inside: Debian 12, `kicad-cli` 9.0.8, `pcbnew` 9.0.8, 224 symbol libraries, `git`,
glibc 2.36, and Python 3.11 with **neither `pip` nor `ensurepip`**. It runs as a
non-root user, so `apt-get` needs `--user root`.

The `kicad-9.0-releases` PPA is live but tracks the newest 9.0 point release rather
than a pinned one. The image pins the exact build of both `kicad-cli` and `pcbnew`,
which is what every ADR in this repository is calibrated against.

While confirming the tag we found **`kicad/kicad:10.0.5` is published**. KiCad 10 is
out and nothing here has been measured against it — recorded as debt in ADR 0013
rather than discovered later, which is the entire point of `CLAUDE.md`.

### 4.2 How much of the suite is invisible without KiCad

Measured, not estimated:

| Environment | Result | Wall |
|---|---|---|
| `python:3.12-slim`, no KiCad | **427 passed, 847 skipped** | 17 s |
| `python:3.13-slim`, no KiCad | same | 17 s |
| `kicad/kicad:9.0.8`, its Python 3.11 | **1 failed**, 3 skipped | 32 m 21 s |
| `kicad/kicad:9.0.8`, uv Python 3.12 | **1271 passed, 3 skipped** | 30 m 38 s |

**Two thirds of this suite does not run on a bare runner.** That single number is
the argument for paying for the container, and it is why the no-KiCad job is a
canary and not a gate.

### 4.3 The failure that had nothing to do with KiCad

One test failed in the image and passes on the development machine. Not flaky: 3 of
3 failures in the image, 3 of 3 passes on the host. Bisected with KiCad's libraries
mounted into stock Python images, so KiCad was held constant:

| Python | numpy | shapely / GEOS | result |
|---|---|---|---|
| 3.11.16 | 2.4.6 | 2.1.2 / 3.13.1 | **fails** |
| 3.12.14 | 2.5.2 | 2.1.2 / 3.13.1 | passes |
| 3.13.15 | 2.5.2 | 2.1.2 / 3.13.1 | passes |
| 3.14.7 | 2.5.2 | 2.1.2 / 3.13.1 | passes |

numpy is not the variable — **numpy 2.4.6 under Python 3.14** (old library, new
interpreter) passes. shapely and GEOS are identical in every row.

The mechanism is CPython 3.12's switch to Neumaier compensated summation for
`sum()` of floats:

```
py3.11: sum([0.1]*10 + [1e16, -1e16]) = 0.0
py3.12: sum([0.1]*10 + [1e16, -1e16]) = 1.0
```

`aipcb.route` costs paths with `sum(math.dist(a, b) for …)` in `geometry.py:299`,
`graph.py:140` and `meander.py:52`. A cost differing in its last bits flips a
comparison in the negotiated-congestion search, the search takes another branch,
and on a deliberately tight probe board one net becomes unroutable.

**Determinism is the project's most-stated promise, and it did not hold across the
supported range.** `requires-python` was `>=3.11`. It is now **`>=3.12`**, with the
measurement written into `pyproject.toml` beside the constraint. The underlying
summation defect is filed as an issue: fixing it moves routing output on every
board and every golden file, which is a milestone, not a line in a CI ADR.

### 4.4 Two interpreters, on purpose

The obvious reading is that CI is stuck — the image's `pcbnew` is built for its
system Python 3.11, and aipcb needs 3.12.

It is not stuck, and the reason is ADR 0009. aipcb never imports `pcbnew` in its own
process; it *probes* for an interpreter that can, and the helper imports nothing
from aipcb. So the KiCad job installs Python 3.12 with `uv` for aipcb and leaves
`pcbnew` on the image's 3.11. Measured in the image:

```
aipcb runs on:  Python 3.12.14
pcbnew runs on: Python 3.11.2 with pcbnew 9.0.8
kicad-cli 9.0.8
```

`uv` installs in **2.4 s**; the 3.12 venv with aipcb in it, **4.6 s**.

A boundary drawn for one reason turning out to solve an unrelated problem three
milestones later is the strongest argument for ADR 0009 that this project has.

### 4.5 The gate, run on the tree being committed

Every CI job was run locally against the exact tree in this commit, inside the
image CI will use:

```
ruff OK
mypy: Success: no issues found
123/123 Python files carry an SPDX header
all permissive (BSD/MIT-family or equivalent)
1271 passed, 3 skipped in 1838.93s (0:30:38)
```

The three skips are the three that *should* skip, and each names itself:
`overconstrained` exists to be unroutable, the flagship-board corpus check is
behind `AIPCB_FULL_CORPUS=1`, and the openEMS integration test needs a container
runtime inside a container, which is not available here. **Nothing skips for want
of KiCad**, which was the whole objective.

Two deltas landed after that export and were verified separately rather than
silently: `mypy`'s scope was widened to include `tools/` (97 files, clean) and
`tools/make_images.py` was made type-clean. Neither is imported by any test —
`grep` over `tests/` and `src/` for `import tools` returns nothing — so the suite
result stands.

## 8. The citation remap, and what the rewrite cannot undo

### 8.1 Commit citations were remapped after the rewrite

The delivery reports cite commit hashes — "fixed in `d5452a6`", "measured at
`3fadee9`". The rewrite in §1.4 changed every one of those hashes, so every
citation in `docs/` pointed at an object that no longer existed. They were remapped
rather than left to rot: `d5452a6` is now `1e0a6a2`, `3fadee9` is now `4599b95`,
and so on for seventeen more. The two old hashes in the sentence above are the
last un-remapped ones in this repository, kept because the sentence is *about*
what a citation looked like before the sweep — a verification pass that flags
them is working correctly.

The old→new map was rebuilt from the pre-rewrite bundle taken before the rewrite:
59 old commits and 59 new ones, paired in `rev-list --reverse` order and then
**proved** rather than assumed — every pair matches on both tree hash and subject
line, 59 of 59, which is the same evidence that showed the rewrite moved no
content.

Every 7-to-40 character hex token in every tracked `.md` was then classified:

| | |
|---|---|
| commit citations, remapped | **19 distinct hashes, 38 occurrences**, across 6 files |
| ambiguous (prefix of more than one old commit) | **0** |
| hex that is not a commit hash, left alone | **19** — KiCad file-format versions (`20241229`), schematic UUIDs, `aipcb`'s own content hashes, upstream gerber2ems and openEMS commit SHAs, a container image digest, an ISBN, a paper id |

Replacements are the same length as what they replace, so table alignment and
prose are untouched. After the sweep, all 19 remapped tokens resolve to real
commits in the pushed history; the 19 others are correctly not commits.

Two exceptions are worth naming because a reader will otherwise trip on them.

**`3bb475e` in §1.3 is deliberately not remapped.** It is evidence about an object
that was publicly fetchable from GitHub under that name, and rewriting it to its
post-rewrite hash would make the sentence assert something false.

**`db1f5ba` in `orchestrator-log.md` never resolved.** It is not a casualty of the
rewrite — it is absent from the *pre*-rewrite history too, checked against the
bundle. It is a citation that was wrong when it was written, most likely because
the commit it named was amended afterwards and the report was not updated. It is
recorded here rather than silently repointed at a guess.

### 8.2 The exposure the rewrite cannot undo

Stated plainly, because §1.3 is easy to read as though the problem were solved.

**The repository was public with the old history, and that cannot be recalled.**
From 2026-08-21 until the flip below, `mikkelmi2/aipcb` was public, and every
commit in it carried a personal email address and three `claude.ai` session URLs.
Anyone or anything that cloned, mirrored, scraped or cached the repository in that
window holds that data, and no action taken here reaches it. Search-engine caches,
third-party GitHub mirrors, archival crawlers and any fork made in that window are
all outside this project's control.

**And the old objects survive on GitHub after the force-push.** Unreferenced
commits stay resolvable by SHA on a public repository until GitHub garbage-collects
them, which is not guaranteed to happen on any schedule and can require asking
GitHub Support. Someone holding an old hash can still read the old commit.

**What the rewrite does achieve** is bounded and worth having: every clone from the
force-push onward is clean, the branch history is clean, and the address is no
longer discoverable by browsing the repository, only by already knowing a hash.
That is a reduction in exposure going forward. It is not an erasure of the past,
and this report does not claim to be one.

**What could not be established**, unchanged from §1.3: whether the address reached
third-party archives that record public push events. The repository's 22 available
public events carry no commit lists, so nothing was found by that route — which is
not the same as nothing having been captured.

The mitigating facts remain as measured: 0 forks, 0 stars, 0 watchers, no
description, no licence, never announced, for the whole window.

# M15.1 — maturity labels: lead with what is proven, mark the router beta

A documentation milestone whose entire behavioural change is one line of output.
M15 made the repository
public with a README that presented everything at one level of confidence — the
source format that fifteen milestones hardened sitting beside an autorouter that
has never been given a board this project did not design. Both were described in
the same voice. M15.1 separates them.

The framing that makes the label cheap was decided before anything was written:
**routing is one declared step, it fails loudly, and manual layout is first-class.**
A beta label on an optional, loud-failing step is information. The same label on a
step you cannot avoid and that fails quietly would be an apology, and the README
would have had to hedge everywhere to earn it. It does not.

## 3. The graduation criteria

Written into [`docs/roadmap.md`](../roadmap.md#maturity-and-graduation) so the label
is a measurement plan and not a permanent hedge. The README carries a one-sentence
summary and links to it.

**Autorouting comes off beta when all three hold:**

1. it has routed **five externally-contributed boards** end to end — boards this
   project did not design, which is the one piece of evidence the example corpus
   cannot supply no matter how large it grows;
2. a **congestion stress example harder than `examples/congestion`** — more nets
   than channels, an outline with no slack — either routes or hands over cleanly,
   so the behaviour at the limit is known rather than discovered by a user;
3. its **runtime is benchmarked against board size**, so that "it will not finish"
   can be distinguished from "it has not finished yet".

**SI simulation comes off beta when** all eleven flagship links extract physically
(`PCIE_TX` is the one that does not) **and** one simulated impedance has been
checked against a measured test coupon. The second condition needs a fabricated
board, which this repository still does not have — the same fact the README's last
paragraph already carried.

Neither is a date. Both are conditions somebody else can check.

## 4. The one code change, and its test

`aipcb route all` and `aipcb route check` each emit one line **on stderr**:

```
note: autorouting is beta - proven on this repository's examples, not yet on
boards it did not design. https://github.com/mikkelmi2/aipcb/blob/master/docs/
roadmap.md#maturity-and-graduation
```

(one line in the terminal; wrapped here to fit the page)

Three decisions in that, each with a reason:

* **stderr, not stdout.** `route all | something` must not get a marketing line in
  the pipe. This was not hypothetical — `tests/test_routing.py` and
  `tests/test_multilayer.py` both do `json.loads(result.stdout)`, and stdout would
  have broken them.
* **suppressed entirely under `--json`.** A machine consumer gets no prose at all;
  the tests assert `result.stderr == ""` on both JSON paths.
* **the same fact, structurally, in the report.** `routing.maturity == "beta"` for
  `route all`, `routes.maturity` for `route check`. An agent reading the report sees
  the label without parsing English for it, which is the form this project's output
  is supposed to take.

`TestBetaNotice`, five tests:

| test | what it pins |
|---|---|
| `test_the_notice_is_one_line_on_stderr_with_a_link` | exactly **one** line mentioning beta, carrying `BETA_DOCS_URL`, and **nothing** about beta on stdout |
| `test_route_check_says_it_too` | `route check` is not a quiet back door to the router |
| `test_json_carries_the_label_structurally_and_not_in_prose` | `stderr == ""` under `--json`, and `routing.maturity == "beta"` |
| `test_json_is_schema_stable_apart_from_the_new_field` | the top-level keys are unchanged, and the routing block's keys minus `maturity` equal the frozen pre-M15.1 set exactly |
| `test_route_check_json_carries_it_as_well` | `routes.maturity`, and a silent stderr |

The schema-stability test is the one that matters, and it is written as an
**equality** against a frozen key set rather than a containment check, so a future
key added to the route report fails it and has to be declared deliberately. The one
conditional key, `stitching`, is excluded by name rather than asserted absent — it
depends on the design declaring a stitching pattern, and `ldo-supply` does not.

`ruff check .` and `mypy` clean over the tree. `test_routing.py`,
`test_idempotence.py` and `test_multilayer.py`: **86 passed, 0 failed**.
`test_manual_routing.py`, `test_check_loop.py`, `test_export.py`,
`test_highspeed.py` and `test_mechanical.py`: **232 passed, 1 skipped, 0 failed** —
these are the five other suites that shell out to `aipcb route` and parse its
stdout, and they are what would have caught the notice landing in the wrong stream.
`tools/add_spdx.py --check` and `tools/check_licenses.py` also pass; `CHANGELOG.md`
is markdown, and the SPDX gate covers Python files only.

It is 31 added lines in `cli_route.py`, and all
but four of them are the helper, its two constants and their comments — the working
part is two `_beta_notice(as_json)` calls and two assignments.
